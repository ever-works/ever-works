## Decisions

1. **The management lane already existed (FL-02 T-27).** FL-16 is the first epic to register kinds: contracts'
   `FLEET_MANAGEMENT_LANE_KINDS` = `['vm-create', 'vm-control']`, both needing `manage`. The FL-02 specs that pinned
   the list as empty ("until an epic registers a kind") now pin FL-16's two kinds — the test was written to be
   evolved by this epic, and it asserts strictly more than before.
2. **Queue SLA for the VM jobs is 2 h, not the plan's 1 h / 10 min.** Like `computer-session` and `agent-session`,
   they do not undercut the shortest existing default, which is what an unknown kind fails closed to; lowering it
   would change every older reader's answer for an unknown kind.
3. **A `virtual-host` capability tag (additive, CONTRACTS §1.2 question).** Every `vm-*` job requires `managed`,
   `docker` AND `virtual-host`; only a node that runs FL-16's executors advertises the last one. Without it an
   FL-02-era node started with `--work --manage` on a Docker host would lease a `vm-create` through its work lane
   (it does not know the kind is the management lane's) and fail it.
4. **The host resolves the image, the platform never names one.** `vm-create` carries the `systemId` only; the
   node maps it through its OWN catalogue (with operator overrides) and reports the `ref@digest` it used, which is
   stored in `virtualMeta.image` and shown on the child. The host therefore executes only catalogue images even if
   a job payload were forged.
5. **Progress rides the durable job, not a link operation.** The node reports each phase through a node-credential
   internal endpoint (`POST /api/internal/fleet/virtual/:childId/progress`, authorised like `push-credential`:
   the job, its holder, its lease generation) and the platform stores it on the child's `virtualMeta`. The
   `operationId` a create / power / destroy answers is the job id. Reason: a create is a durable job that must
   survive link drops and platform restarts (U9); FL-02 operations live in one API replica's memory and are tied to
   a link request. The hub polls the children every 5 s while one is busy (FR-13).
6. **Image pinning is trust-on-first-use until the owner supplies digests.** The catalogue names a tag per system;
   the first pull on a host resolves the digest and records it in `<node data>/virtual/catalogue.lock.json`, and every
   later create on that host runs `ref@sha256:…`. An operator override (`EVER_WORKS_NODE_VIRTUAL_IMAGE_<SYSTEM>`)
   may name a full `ref@sha256:…`. Owner question 2.
