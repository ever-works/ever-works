## Decisions

(Numbered so later notes can refer to them.)

1. **Session link messages live in FL-04's `fleet-sessions.types.ts`, not in FL-02's `FleetLinkControlMessage`
   union.** `session.event` / `session.list` / `session.ack` are channel-0 _extension_ messages: putting them in
   `FLEET_LINK_CONTROL_TYPES` would route them to the registry's `onControl` instead of
   `FleetLinkRegistry.onNodeControl(type, …)`. A spec pins that they never collide.
2. **One session channel per attached viewer, one short-lived channel per control request.** CONTRACTS §3.3 opens
   the family with `{ sessionId, mode }`; FL-04 adds optional `kind` so the node can check `--manage` (owner) vs
   `--work` (Agent) before it opens (R-5), and re-checks against the daemon's own record. Verbs:
   `session.start|attach|input|resize|end|rename|restart|screen|answer` (`answer` refused until FL-05).
3. **CONTRACTS additions this lane must write into `CONTRACTS.md` in PR 1 (not done yet — see Next step):**
   §1.1 daemon block gains `storage?: 'ok'|'failing'` (spec U15); §3.3 session family gains the `session.screen`
   verb, the platform→node channel-0 `session.ack { sessionIds }`, `session.list` carrying `daemon`, the
   `session.notice` notices (`paused · resumed · drain · slow-viewer · size · replay`) and optional `reason` on
   `session.event exited`; §4.1 `FleetNode.sessionDaemon` (simple-json, FL-04 slot 00); §4.2
   `FleetSession.exitCode` (int null) and `startedBy` (varchar 80, `user:<id>|agent:<id>`).
4. **`daemonSessionId` = the platform's row id at start.** The node addresses by it; `(nodeId, daemonSessionId)` is
   unique. The column stays separate so a later node-originated session needs no migration.
5. **Owner-session starts write their row only after the node confirmed the process runs** (state `working`, no
   `starting` phase for owner sessions), under a per-node advisory lock that re-counts the eight-session limit; a
   start that lost that race ends the process it just started and answers `limit_exceeded`. No phantom rows, no
   deleted rows. Node events that beat the row are held 10 s and applied when it lands.
6. **Process exit → `ended (exit)`**, outcome from the exit code (spec U14), kept as the first outcome written
   (FL-05 may set one earlier). User/drain/kill-switch ends → outcome `cancelled`; lost/timeout → `unconfirmed`.
7. **Node state refusal code is `busy`** (paused / disabled / enrolling, FR-39) — CONTRACTS §8 has no node-state
   code; `busy` is the nearest ("exclusive thing held"). Question Q2.
8. **No pipe floor in the daemon.** The PTY is `@homebridge/node-pty-prebuilt-multiarch` (lazy require, the
   range pty-local ships, `^0.13.1`); without it the daemon reports `pty: missing` and the node withdraws
   `sessions` with the fix in words. Tests use test-only hosts (`__tests__/pty-test-kit.ts`: an in-memory PTY and
   a real child process over pipes).
9. **Latest versions:** `@xterm/headless` 6.0.0 and `@xterm/addon-serialize` 0.14.0 (latest) added to
   `apps/node`. **Held back:** `@homebridge/node-pty-prebuilt-multiarch` stays `^0.13.1` (0.14.1 is latest): the
   bundle (`apps/node/build.js`) reads the range from pty-local's manifest, so a bump changes the cloud terminal
   host too, and the native prebuild cannot be proven here (the workspace never builds it — it is not in
   `onlyBuiltDependencies` — and fetching it is a download this lane may not make). Retry with a proven install.
10. **Owner session folders** must be inside the home folder or an extra root (plan §11); `~` expands; symlinks
    resolved. Windows compares without case. A Windows `.cmd`/`.bat` CLI never gets the first message on its
    command line (cmd.exe would re-parse `& | ^ %`): it is typed into the session 1.5 s after start.
11. **Daemon wire:** frames `[kind u8][len u32][payload]` (CONTRACTS §3.2 kinds without the channel), token-first
    hello (constant-time, re-read per hello, 4 KiB cap before auth, pipelining refused), control vs attach
    connections; every control connection counts as "a node connected" for the idle rule.
12. **Sessions tag is dynamic:** the runtime now re-reads module tags on every beat (`currentEnvironment()` in
    `runtime.ts`), so `sessions` follows the daemon's health (FR-10). `sessions` is non-selectable like `managed`.
13. **Heartbeat tier:** `daemon` is the newest strip tier; `describeStrippedTiers` now names the fields dropped
    instead of the tier index.
14. **`NodeLink.sendControl`** added (additive, FL-02's file) so a module can send channel-0 messages that belong
    to no channel; the session module binds the link via `bindLink(link)` (runtime) for facts, kill switch, drain.
15. **Windows service:** NSSM `AppKillProcessTree 0` (T-19), tested in `test-install-service-logic.ps1`.
    **systemd unit left unchanged** (its default `KillMode=control-group` and `ProtectHome=read-only` apply to the
    daemon); documented in `apps/node/packaging/README.md`. Question Q1.
16. **End needs `confirm: true`** (CONTRACTS §2.2 class `confirm`); without it `confirmation_required` with the
    summary "End "<title>" on <computer>? The process is stopped; its screen is kept."

## Questions for the owner

(Also OWNER-QUESTIONS A7, A8, B3 — the three open epic questions; their defaults are built: owner sessions not
recorded by default, several drivers allowed, `pwsh` else Windows PowerShell.)

- **Q1 — Linux service installs.** Under the hardened `ever-works-node@.service` (system unit), a service restart
  kills the session daemon (cgroup kill) and `ProtectHome=read-only` keeps owner sessions from writing to home.
  Options: ship a drop-in with `KillMode=process` + `ProtectHome=false` (a crashed node then leaves job processes
  behind, which the existing quarantine gate catches), or document running the node as a `systemctl --user`
  service for machines that host owner sessions. Built: unit unchanged, README says so.
- **Q2 — refusal code for a paused / disabled node** (FR-39): built `busy` with `details.nodeState`. A dedicated
  code would be a CONTRACTS §8 change.
- **Q3 — `onlyBuiltDependencies`.** The workspace never builds the PTY addon, so a node run from the monorepo
  (not the npm bundle) never advertises `sessions`. Adding the addon to `pnpm-workspace.yaml`
  `onlyBuiltDependencies` would make every install download its prebuild. Built: unchanged.
