## Decisions

1. **A new contracts file, `fleet-schedules.types.ts`,** holds the cadence, the clock, the `schedule` family's
   messages and the views (plan §4.3 put the link messages in `fleet-commands.types.ts`; one file per family
   keeps FL-12's file as it merged). `FleetCommandRunView` gains only the optional `scheduledFor`.
2. **One clock for three consumers.** `nextFleetScheduleFire` / `previousFleetScheduleFire` /
   `fleetScheduleCatchUp` are pure (`Intl.DateTimeFormat` only) and shared by the API, the node and the web. A
   wall time a spring-forward day skips fires as far past the jump as it was scheduled before it (02:30 → 03:30);
   a repeated fall-back time fires once, at the first of the two; "every N minutes" is the cron `*/N` of the
   minute field (it restarts every hour). A computer that never reported a zone runs on UTC.
3. **Name length 120** (CONTRACTS §10 wins over the spec's 80).
4. **`pausedReason` values are CONTRACTS §4.4's** `user · failures · breaker` (plan §4.1 said `failure-streak`).
