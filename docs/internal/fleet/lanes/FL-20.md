## Decisions

1. **The management lane already existed (FL-02 T-27) and FL-16 had registered the first kinds.** FL-20 appends
   `usage-scan` to `FLEET_MANAGEMENT_LANE_KINDS` with the consent `usageScan` (CONTRACTS §1.1, R-34). The FL-16-era
   specs that pinned the list now pin three kinds; `--manage` alone never leases the scan and `--usage-scan` alone
   leases only the scan.
2. **Rows are cumulative per bucket; the platform merges with a field-wise maximum.** A row is the node's running
   total for one bucket (provider × provider session × model × hour × folder bucket), not an increment. The
   platform keeps `max(stored, reported)` per token class, so a re-sent report (lost acknowledgement, node state
   lost and everything re-read) never double counts and a deleted record file never subtracts (FR-4, U4, U5). Each
   bucket carries a node-local revision; the report's `watermark` is the highest revision it carries and the next
   job's payload hands back the newest ACKNOWLEDGED watermark as `since`, so the node re-sends exactly what the
   platform has not stored.
3. **The samples table (`fleet_usage_samples`, slot 01) ships in P1, not P2.** The cumulative/max design needs a
   per-bucket store on the platform from the first report; holding buckets inside `fleet_sessions.tokens` and then
   migrating them to a table in P2 would be two sources of truth for one number. P2 is therefore only surfaces. The
   Session's `tokens` / `costCents` (slot 00) are a cache DERIVED from its samples on every report.
4. **Report cap 500 rows, not 2 000.** A row is ~330 bytes on the wire; 2 000 rows (~660 KB) would not fit the
   existing job result cap (`FLEET_JOB_MAX_RESULT_BYTES` = 256 KiB) and every report would be refused. 500 rows plus
   a 192 KiB byte belt; a larger backlog drains over several scans (`truncated`, `backlogPct`, U11).
5. **Queue SLA for `usage-scan` is 2 h, not 15 min**, for the reason FL-16 decision 2 gives: no kind undercuts the
   shortest existing default (the fallback an unknown kind fails closed to). The dispatcher never enqueues a second
   scan for a node while one is queued or leased, so a stale scan only delays the next.
6. **Cost is priced from summed tokens per (model, price-list version), never from summed rounded cents.** Each
   sample keeps the version it was first priced with (U8: figures are not re-priced silently); an aggregate groups
   tokens by model and version, prices each group with that version's rates and rounds once. A sample's own
   `costCents` (CONTRACTS §4.10) is that one hour's rounded figure, for display only.
