## Decisions

1. **The management lane already existed (FL-02 T-27) and FL-16 had registered the first kinds.** FL-20 appends
   `usage-scan` to `FLEET_MANAGEMENT_LANE_KINDS` with the consent `usageScan` (CONTRACTS §1.1, R-34). The FL-16-era
   specs that pinned the list now pin three kinds; `--manage` alone never leases the scan and `--usage-scan` alone
   leases only the scan.
2. **Rows are cumulative per bucket; the platform merges with a field-wise maximum.** A row is the node's running
   total for one bucket (provider × provider session × model × hour × folder bucket), not an increment. The
   platform keeps `max(stored, reported)` per token class, so a re-sent report (lost acknowledgement, node state
   lost and everything re-read) never double counts and a deleted record file never subtracts (FR-4, U4, U5). Each
   bucket carries a node-local revision; the report's `watermark` is the highest revision it carries and the next
   job's payload hands back the newest ACKNOWLEDGED watermark as `since`, so the node re-sends exactly what the
   platform has not stored.
3. **The samples table (`fleet_usage_samples`, slot 01) ships in P1, not P2.** The cumulative/max design needs a
   per-bucket store on the platform from the first report; holding buckets inside `fleet_sessions.tokens` and then
   migrating them to a table in P2 would be two sources of truth for one number. P2 is therefore only surfaces. The
   Session's `tokens` / `costCents` (slot 00) are a cache DERIVED from its samples on every report.
4. **Report cap 500 rows, not 2 000.** A row is ~330 bytes on the wire; 2 000 rows (~660 KB) would not fit the
   existing job result cap (`FLEET_JOB_MAX_RESULT_BYTES` = 256 KiB) and every report would be refused. 500 rows plus
   a 192 KiB byte belt; a larger backlog drains over several scans (`truncated`, `backlogPct`, U11).
5. **Queue SLA for `usage-scan` is 2 h, not 15 min**, for the reason FL-16 decision 2 gives: no kind undercuts the
   shortest existing default (the fallback an unknown kind fails closed to). The dispatcher never enqueues a second
   scan for a node while one is queued or leased, so a stale scan only delays the next.
6. **Cost is priced from summed tokens per (model, price-list version), never from summed rounded cents.** Each
   sample keeps the version it was first priced with (U8: figures are not re-priced silently); an aggregate groups
   tokens by model and version, prices each group with that version's rates and rounds once. A sample's own
   `costCents` (CONTRACTS §4.10) is that one hour's rounded figure, for display only.

7. **The consent is a process flag, not a stored setting.** `--usage-scan` is process-scoped like `--manage`
   (CONTRACTS §1.1, FL-02's consent model: consents ride the environment and the heartbeat, never the stored
   config). tasks.md T-07's `usage-scan on|off` verbs and a persisted `usageScan` are therefore NOT built — a
   stored switch would be a second source of truth for a consent. `status` prints the state and the privacy
   sentence from the link record.
8. **Each record is admitted once, by its provider ids, with per-class GROWTH.** Claude Code writes one line per
   content block of a response with the same `message.id` + `requestId`; a later line can carry the final output
   count. The node remembers the counted tokens per record identity (a 20-hex hash, never content) and adds only
   the growth; the request is counted on first sight. Codex `token_count` events are identified by session id +
   cumulative totals, so a re-emitted (rate-limit-only) or replayed event counts once; tokens come from
   `last_token_usage` (input includes cached input on that provider), else the growth of `total_token_usage`.
9. **Node state is bounded by pruning, safe because of decision 2.** Record identities are kept 35 days by record
   hour; a bucket is dropped only once the platform acknowledged it, nobody touched it for 2 days and its hour is
   older than 35 days. A record re-read after that re-enters a fresh bucket and the platform's maximum keeps the
   larger stored figure (a figure can lag, never double). A `since` ahead of the node's revisions (state lost)
   re-stamps every bucket so none is skipped.
10. **An over-long line is skipped across scans.** The line reader keeps a per-file `skip` flag when a scan stops
    inside a line longer than 1 MiB (never parsed), so a line bigger than one scan's budget cannot stall a file.
11. **The Run receipt's line comes through a port.** `RUN_RECEIPT_FLEET_USAGE_READER` (agent `agents/`), optional
    in `RunReceiptService`, bound api-side to `FleetUsageViewService` in the global `FleetUsageApiModule`; the
    receipt gains an optional `fleetUsage` field (contracts `RunReceiptFleetUsage`).
12. **Flag off hides the session figures at the source.** `toFleetSessionView` carries `tokens` / `costCents` only
    while `FLEET_USAGE_SCAN_ENABLED` is on, so the chip disappears with the flag without a web flag read.
13. **The dispatcher runs as an API cron** (`FleetUsageScanCronService`, `DistributedTaskLockService`), not a
    Trigger.dev task: one read and one enqueue per computer, idempotent per 15-minute window — the FL-14 / FL-17
    sweep shape. tasks.md T-14's `packages/tasks` file is not built.
14. **MCP: `fleet_usage_get` is refused for a fleet-run token** (named in `whitelist-fleet-run-surface.spec.ts`): a
    run on a machine has no business reading its owner's model spend across computers. A person's MCP client
    reads it.
15. **Price list v1 (2026-10-26)** carries the current Claude families (Fable 5.1 / 5 with the Mythos ids,
    Opus 5.5 / 5 / 4.8 / 4.7 / 4.6, Sonnet 5.5 / 5 / 4.6, Haiku 5.5 / 4.5) and the earlier ones, plus the OpenAI
    families Codex runs. The 5-minute cache write is taken as 1.25 × input for every Claude family.

16. **P2's two reads extend the one Usage object.** The Agent page's rows are `GET /api/fleet/usage?agent=` (the
    view filtered to rows attributed to the Agent's sessions or Task runs; "other" rows never belong to an Agent);
    the schedule rows are `GET /api/fleet/usage/tasks?ids=` (each recurring Task's newest Run and its 30-day total,
    the caller's OWN Runs only — a schedule is its owner's). Neither is an MCP tool (the hub reads them).
17. **The tab keeps its filters in component state**, seeded from `?days=`, `?node=`, `?model=` (the computer
    Overview line and the palette link with `?node=`); clicking a computer or a model filters, a chip clears it.
    "Scan now" is offered on owner-role, online, opted-in computers only (the API refuses everyone else anyway).

## Questions for the owner

1. **Price list v1 rates.** `packages/agent/src/usage/model-list-pricebook.ts` carries the providers' published
   pay-as-you-go rates as this lane knew them on 2026-10-21 (Claude and OpenAI families the two CLIs use). Please
   verify them; any model not in the table is counted in tokens only and never priced at $0 (FR-8).
2. **CONTRACTS §4.10 epic-local columns.** Besides `priceListVersion` and `dedupeKey` (already listed), the samples
   table carries `agentRunId` (the Task run a row was attributed to when there is no Session — R-13's second key).
   Please add it to §4.10.
3. **Should "other" sessions be visible to Organization members** in the computer's `view` audience (spec §8b)?
   Built: owner only; members see that total as "not shown".
4. **Price list v1 assumptions.** (a) The 5-minute cache-write rate is 1.25 × input for every Claude family (the
   published rule for the earlier ones); (b) Haiku 5.5 is priced at its ≤ 100 K-token prompt tier — its long-prompt
   tier ($0.50 / $2.50) needs the per-request prompt size, which the hourly buckets do not keep; (c) the OpenAI
   rates (GPT-5 family, o3, o4-mini, GPT-4.1, GPT-4o, codex-mini) are as this lane knew them. Please check before
   the flag is switched on anywhere.
5. **`usage-scan on|off` verbs** (tasks.md T-07) were not built (decision 7). Want a persisted switch as well as the
   flag (e.g. for a node installed as a service)? The service install would then carry `--usage-scan`.
6. **`excluded.nodes`** in the Usage view is always 0 in P1: counting an Organization's computers a member may NOT
   see would tell them those computers exist. Built: say only that "other" sessions are hidden. Want the count?
