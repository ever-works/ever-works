## Decisions

1. **No tar, no archive library: a "files stream" of contract records, and a hand-written zip.** The plan picked
   `tar-stream` and `archiver`, neither of which the node or the API may import without a lockfile change (the
   lane cannot run `pnpm install`). The wire format is the contract's own (`fleet-files.types.ts`): records
   `[tag u8][length u32][body]`, a JSON header per entry, the file's bytes in records of ≤ 64 KiB, every `DATA`
   frame holding whole records, `END` to finish. The SAME stream goes both ways, so P2's copy pipes frames
   between two channels without reading them. The browser's `.zip` is built on the platform by
   `apps/api/src/fleet/files/fleet-files-zip.ts` (store only, data descriptors, UTF-8 names, links as links).
2. **Upload has no multipart.** The browser builds the same files stream as a lazy `Blob` (headers plus
   `file.slice` parts — nothing read into memory) and sends it as `application/octet-stream`; the BFF pipes it
   (`duplex: 'half'`), the API re-frames it into whole records, proves each one (contract decoder + tracker:
   no path out, exact sizes, ≤ 5 000 entries, ≤ 2 GiB) and forwards each `DATA` frame only against the machine's
   `ACK` credit — reading the request no faster than the machine writes.
3. **The services live in the API** (as FL-08's): `FleetFilesService` (roots, list, stat, conflicts, delete,
   download check, the list audit) and `FleetFilesTransferService` (download, upload, transfers, cancel) in
   `apps/api/src/fleet/files/`; the Agent tools are in `packages/agent/src/fleet/files/` and read through a port
   (`FLEET_FILES_READER`), offered when `AgentFleetToolSource.files` is bound — FL-19 assembles them.
4. **Hidden = a leading dot, on every system.** The Windows hidden attribute and macOS `UF_HIDDEN` need native
   calls the node does not make (plan §6.2 lists them); a dot-file is hidden everywhere.
5. **Additive vocabulary** (CONTRACTS amendment asked below): `files.roots` is a `machine` verb (the
   `logs.sources` precedent) and the verb prefix `files` answers to the `files` family; the `files` channel adds
   `files.conflicts` (FR-12) and `files.pack { dryRun: true }` (the **download check**: counts and the
   credential-shaped files inside, nothing streamed — so the dialog shows before the browser starts a download);
   the node sends `files.packed` before `END` and `files.unpacked` after an unpack.
6. **Per API replica**: the transfer records (the Operations strip), the concurrency caps (2 per computer, 4 per
   person), the once-per-visit list audit (15 minutes per person, computer and root) and today's bytes. The
   node's FL-02 operation id is tracked (`FleetOperationsService.track`), so `DELETE …/files/transfers/:id`
   falls back to the shared FL-02 cancel when the transfer runs on another replica.
7. **Credential-shaped files are found by the machine, folders included**: `files.pack` walks the selection and
   refuses `confirmation_required` (class `confirm`, the names) unless `allowCredentialShaped`; the platform
   sets it only for a person who confirmed, and turns the refusal into `permission_denied` for an Agent (FR-17,
   U13 — no override).
8. **Replace replaces the whole entry**: a replaced folder is set aside inside the partial folder, the new one
   renamed into place, the old one removed with the partial folder (restored if the rename fails).
9. **The browser downloads through a hidden frame after the check**, so the page stays where it is; a refusal
   that slips past the check (a race) shows as a failed row in the Operations strip.
10. **Delete's typed name at a root's top** (several entries, no folder): the root's own folder name — the
    server resolves it from the roots list, the dialog from the same rule (`deleteConfirmName`).
11. **Today's bytes** are per computer per UTC day (spec §8b default says the viewer's time zone — see the
    question below).
12. **No Activity Log rows** for transfers: no fleet epic writes Activity rows yet; the `node.files.*` audit rows
    and the Operations strip are the record (question below).
13. **Windows links on upload**: creating a symlink needs a privilege a plain node does not have; a link that
    cannot be created is skipped and counted (`skippedLinks`), never followed.
14. **Copy was visible but disabled in P1** (_"Copying between computers arrives next"_); P2 wired it.
15. **FL-19's tool catalogue** (`packages/contracts/src/fleet/fleet-tools.types.ts`, landed during P1): the files
    rows are FL-11's, so P1 adds `fleet_files_roots` (live), makes `fleet_files_list` / `fleet_files_stat` live and
    points the list's route at the route built (`GET …/files/list`; the planned row said `…/files`). P2 makes
    `fleet_files_copy` and `fleet_files_delete` live (copy now `alwaysHeld`, like delete). Download and upload
    stay `planned` (no Agent moves bytes to or from a browser); `fleet_desktop_paste` stays `planned` (decision 19).
16. **Copy is a 202 that keeps running on the platform** (P2): the replica that took the request holds both
    channels and pipes them; the answer comes once both computers accepted (the dry-run check — limits and
    credential-shaped files — then the destination's `files.unpack`, then the source's `files.pack`). Frames are
    forwarded unchanged and re-read on the way (decoder + tracker), the destination's `ACK` is forwarded as the
    source's credit (never more than one window ahead), and either side closing closes the other (the
    destination removes its partial folder). A credential-shaped file inside a copy needs `confirm` from a person
    (the same class as a download) and is refused for an Agent.
17. **Paste routes follow FL-19's catalogue, not plan §5's FL-07 path**: `POST /api/fleet/nodes/:id/desktop/paste`
    `{ viewId, agentId, text }` and `GET|PUT …/desktop/paste-switch` (FL-07's `/desktop/views/:viewId` routes do
    not exist yet). The view is today's live view (a computer session, R-27); `agentId` names whose computer it
    shows, so the control arbiter can prove it is the caller's own, live view.
18. **Held Agent acts run as the approving person**: the node link's audience still refuses an Agent caller for the
    `files` family (FL-19 relaxes that), so a person's approval in My Decisions runs the held copy / delete AS THAT
    PERSON through the same services a click takes; the proposal row records the Agent, and a delete's audit row
    carries `approvedProposalId`. The approval is the delete's `confirm-destructive` confirmation.
19. **Paste lands through the view's own injector, not the OS clipboard**: the node's `clip` family hands the
    text to the live view's input injector as `text` inputs (chunks of 4 096 characters, never splitting a
    surrogate pair) — exactly the path a controlling person's typing takes (control held, the Agent paused
    first), so it lands in the focused element of the Agent's browser (`Input.insertText`); no clipboard is
    written and none is read. The desktop source (FL-07's native helper) is not on the node yet: a view that is
    not open answers `unsupported_on_node`. No Agent paste tool: an Agent cannot hold control of a view yet.
20. **The paste switch is in memory per API replica**, keyed by view, owned by the person who set it, and dropped
    the moment the view is found ended; a replica that does not have it reads "off", which fails closed.
