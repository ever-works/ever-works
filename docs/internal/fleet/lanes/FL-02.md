Seams other lanes extend without editing the core:

- **Node**: a module is one file under `apps/node/src/core/link/modules/` plus one entry in
  `modules/index.ts`. A module contributes capability tags, channel families and `machine` verbs.
- **Platform**: `FleetLinkService.request(...)` / `openChannel(...)` (exported also as
  `NodeLinkService`) is the one entry point a controller calls; the per-call requirement (consent,
  action family, state-changing, target) defaults from the family table and can be narrowed per
  verb by the caller.
- **Audience**: the family-audience check is a port (`FLEET_LINK_AUDIENCE`), bound to FL-01's role
  derivation since PR 1's review gate (decision 17).
- **Viewers**: an epic's attach-token route calls `FleetLinkAttachService.mint(...)`; the browser opens
  `/ws/fleet/<family>/<target>` and is bridged — the epic writes no socket code.

## Decisions

Numbered so later notes can refer to them. CONTRACTS revision 5 is the reference.

1. **`--usage-scan` is FL-20's flag.** The audited spec (rev 3) gives the flag to FL-20; this lane reports
   `usageScan: false` in every heartbeat and on the hello, and the consent exists everywhere in the contracts.
2. **Capability-tag default 16 → 32** (`FLEET_DEFAULT_MAX_CAPABILITY_TAGS`, new `FLEET_LEGACY_MAX_CAPABILITY_TAGS = 16`).
   A fully equipped GPU machine with `--attend` already advertises 16 tags, so `managed` (and every program tag
   after it: `logs`, `services`, `ports`, …) would fall off the end. A platform accepting more desynchronises no
   daemon; a newer node facing a 16-tag platform (an older build, or an operator's explicit cap) is answered 400
   and retries its beat with the first 16 tags, latched — never a failed beat. Two pinned tests moved with the
   constant (the contracts pin, and the enroll DTO bound test now uses `default + 1`).
3. **The `machine` channel opens on any link**; each request is checked against its verb's consent from the one
   table `FLEET_LINK_VERB_CONSENT_OVERRIDES` (`manage` unless listed; `health.now` → `link`) on the platform AND
   the node. Node verbs declare no consent of their own, so the two ends cannot disagree.
4. **Requirement narrowing.** A caller may name a stricter consent (`session`: `work` or `manage`), never a weaker
   one — a weaker one is ignored with a warning. A `machine` verb is state-changing unless its action family is
   `view`; a family is state-changing per `FLEET_LINK_STATE_CHANGING_FAMILIES`.
5. **Existence first.** Before kill switch → consent → audience (FR-23), a caller outside the node's `view`
   audience gets `not_found`, as every node endpoint answers a stranger — a refusal never confirms a node exists.
6. **Audience seam (FL-01).** `FLEET_LINK_AUDIENCE` is a port bound in `apps/api/src/fleet-link/fleet-link.module.ts`.
   First bound to `OwnerOnlyFleetLinkAudience` (owner in every family, the owner's schedules and system jobs
   allowed, the owner's own Agent may `view` only, everyone else `not_found`) while FL-01 had not landed;
   **superseded by decision 17** once FL-01 P1a's `FleetAccessService` reached develop.
7. **Kill switch.** Every channel open AND every request is refused `kill_switch` (R-24 "every link request"), the
   switch read fail-closed per call; the gateway polls it every 2.5 s while links exist and sends
   `link.pause` / `link.resume`; a link accepted while paused is paused at once. On the node, pause refuses new
   opens and state-changing verbs, leaves processes running.
8. **Desktop shell untouched until P3.** `createNodeRuntime` builds the link only with `nodeLink: true` (the CLI
   passes it). The desktop shell's heartbeat now reports its consents (`work` only), which is accurate; its link
   view reads `unsupported-kind` until parity ships (R-10).
9. **Audit.** `node.link.connect|disconnect` per accepted link (node actor), `node.consent.change` when a beat's
   consents differ from the stored set (not on a daemon's first report), `node.link.channel-open` for
   state-changing families on both outcomes (`opened`, or `refused` with the node's code) with
   `{ family, target, requestedBy, outcome }`.
10. **Operations.** Node-generated ids (`op-<uuid>`), readable by the requester or the node's owner, updated only by
    the node running them, kept 1 h after the end, failed after 24 h running. `interrupted` (rev 5): a fresh node
    process (hello without the last generation), or a link away past the 2-minute resume window; a late
    completion never changes it. Results that finish while the link is down are delivered after the next ready.
11. **Generations** are `max(last issued, presented) + 1`, so they never repeat for a node across an API restart.
12. **Hello rate** (10/min, then 60 s) counts only hellos whose token verified — counting claimed node ids would
    let anyone lock a node out.
13. **Frames.** ws `maxPayload` is 16 MiB + 1 MiB: a frame between the two closes only its channel `invalid`
    (U5); beyond, ws itself closes the link (1009). `linkVersion` other than 1 closes `4009`.
14. **Close code `4012`** (no consent opens a link) is new in the contracts constants; CONTRACTS lists no close codes.
15. **Single-use link tokens** are enforced per API process until the relay bus lands (PR 2) — accepted by
    CONTRACTS R-7 because multi-replica without the bus is a configuration error.
16. **Audit-name shape test** widened to admit the multi-segment names CONTRACTS §7 fixes (`node.link.channel-open`).
    FL-01 P1a widened the same test on develop (`node.policy.change`); the merge keeps develop's form (any number
    of kebab segments), which admits every FL-02 name.
17. **Audience = the hub's role derivation** (review gate, finding 5). `RoleBasedFleetLinkAudience` asks FL-01's
    `FleetAccessService.roleFor` for the caller's role on the node and checks it with the hub's own
    `fleetFamilyAllows` over the node's control policy: outside `view` → `not_found` for every family; inside
    `view` but not the family → `permission_denied` with FL-01's hint ("Ask the owner of build-01 to allow org
    members: services."). A schedule acts with its owner's role; system jobs are allowed; an **Agent stays
    owner-only** (FL-19 owns the Agent gates; CONTRACTS §2.1 needs both). Without `FleetAccessService` in the
    context it answers owner-only. The link's action families are FL-01's list (same object, same type).
18. **A disabled node keeps its link.** `FleetService.setDisabledForUser` documents that disabling "DRAINS rather
    than severs … the node keeps heartbeating so it remains observable", and drain-all (which disables) warns owner
    sessions over this link. So the hello refuses only a missing row or an `enrolling` one (an owner re-key), and
    a disabled node may still be looked at (health, logs) by whoever its policy allows.
19. **A gone node loses its link at once** (review gate, finding 2): delete, node self-unenrol and an owner re-key
    call `FLEET_LINK_NODE_LIFECYCLE` from the fleet controller (close `4001`); the gateway re-reads the rows of
    the connected nodes every 30 s (`FleetNodeRepository.findStatusesByIds`, chunks of 500) for any other path.
    A failed read closes nothing.
20. **Wire order on accept** (review gate, findings 1 and 3): the registry sends `link.ready` itself, then
    `link.pause` while the switch is on, and only then calls resumed channels' and link listeners. The node lifts a
    pause on every new `link.ready`, so a link that missed a `link.resume` (it was away when the switch cleared)
    is not left paused; a pause still in force is repeated right after ready.
21. **Drain-all tells every enrolled node** (finding 7), an earlier-disabled one too: disabling drains jobs, not
    owner sessions; a node whose job drain failed is told as well.
22. **Generations across a lost ready** (reviewer, lower confidence): a link that dropped before the node sent
    anything on it may never have delivered its `link.ready`; a reconnect presenting the generation that link
    resumed from is the same node process (operations keep running, channels resume).
23. **Early operation updates** (reviewer, lower confidence): an `operation.progress`/`done` that arrives before
    the reply naming the operation was handled (both can be read off one socket chunk) is held 10 s, keyed by node
    and operation, and applied on `track()`; another node's update never reaches it.
24. **Smaller fixes from the gate:** a node-sent `channel.open` is answered `channel.refused` (`invalid`); a request
    cut off by a dropped link answers `unreachable` (`resume_failed` stays a listener reason, not an API code); an
    operation result over the 1 MiB control cap ends `failed` on the node instead of being retried forever; a
    module consent function that throws refuses that open (`internal`); before auth a socket may send only a
    hello-sized frame; the operation routes answer `not_found` while links are off; `channel.refused` also
    reads CONTRACTS §3.2's abbreviated `{ code, hint }` (the wire writes `error: { code, hint }`, as the FL-02
    plan and every reply do).

### PR 2 (relay bus and viewers)

25. **Bus selection is `getRedisUrl()` alone** (`REDIS_URL`, else the throttler's `THROTTLER_REDIS_URL` — the
    readiness check already treats either as "Redis configured"). No mode setting. `FLEET_RELAY_REQUIRE_BUS=true`
    without one fails boot with a message naming the setting and `REDIS_URL`, never the URL (FR-31).
26. **The bus**: two ioredis connections (pub/sub needs its own), a broadcast channel and one per replica, a
    presence beacon every 5 s (a replica silent for 15 s is gone; a newcomer is answered at once), broadcasts
    skipped while nobody else is there, `SET … NX PX` for single-use claims. The publisher keeps no offline queue:
    while Valkey is down a publish is dropped and a claim throws — a single-use token is refused, never accepted
    twice. Every command used exists in Redis 3.0, so the tests also ran against a local `redis-server` 3.0.
27. **Terminal and computer relays ride it** through their existing seams (`TERMINAL_FANOUT_BUS`,
    `COMPUTER_FANOUT_BUS`), as R-7 asks. With the single-replica bus nothing is sent: byte-for-byte the old
    behaviour. The computer seam's synchronous delivery answer reads "the frame went out and another replica
    is there" — pub/sub cannot say which replica holds a machine's leg (its `requested` field can therefore
    read true when no replica has the leg; before the bus it read false whenever the leg was elsewhere).
28. **`fleet_relay` is a top-level key of `GET /api/health/ready`**, beside `version`, exactly the spec's
    `{ configured, mode, status: 'up' | 'degraded' }`: Terminus reserves `status` inside an indicator and
    throws on it. It never fails readiness — a configured Valkey that is down already fails the critical
    `redis` check.
29. **The link across replicas** (`FleetLinkRemote`): a directory announced on accept/drop, re-synced every
    10 s and to a joining replica, expired after 30 s or when its replica leaves; requests, channels (frames
    both ways, requests, close, resume) and channel-0 controls forwarded to the holder; heartbeat consents,
    drain-all and gone nodes fanned out; operation records shared (a finished copy is final, a running copy
    never clears what a replica knows). The caller's replica authorises before anything is forwarded; the
    holder applies its registry's own rules. A newer link on another replica closes the older one `4010`
    (one link per node fleet-wide).
30. **Not carried across replicas, on purpose:** a node's own channel-0 family messages (`onNodeControl`) are
    handled on the replica that holds its link only — replaying them would make every replica write the same
    rows. A link that moves to another replica does not take its resumable channels: they close
    `resume_failed` and the viewers reattach (resume still works when the node returns to the same replica).
31. **Viewer tokens use their own claim `fleet-link-viewer`**, not `fleet-link` as T-21's text says: the node's
    link token already uses `fleet-link`, and a viewer token must never be presentable as a node's credential
    (nor the reverse). Claims carry the node and the open params (≤ 512 bytes); `runId` is `<family>:<target>`
    and must match the socket path. Minting authorises exactly as an open does, for a person only, for a
    computer whose link is up somewhere; 30 a minute per person (per replica).
32. **The viewer gateway re-authorises at open time** (it opens through `FleetLinkService.openChannel` as the
    token's person), so a kill switch or a narrowed audience after the mint still refuses. A `session`
    channel opens with `mode` = the role (CONTRACTS §3.3), so the node enforces read-only too.
33. **Viewer wire** (contracts `fleet-link-viewer.types.ts`): text `{ type: 'auth', token }` first, then binary
    link frames on channel 1 and control on channel 0 (`viewer.ready`, `viewer.refused`, `viewer.resumed`,
    `channel.close` before the close). A viewer may send only `ACK` and its family's listed view controls
    (`FLEET_LINK_VIEWER_JSON_TYPES` — starts with logs and desktop view controls; each family's epic widens its
    own row). Viewer close codes: `4001` auth, `4002` silence, `4009` protocol, `4011` slow reader, `4013`
    channel closed or refused (the reason precedes it).
34. **T-23 lives under `src/`** (`apps/api/src/fleet-link/__tests__/fleet-link.two-replicas.integration.spec.ts`):
    the API's Jest config runs `src/**/*.spec.ts` only, so a file under `apps/api/test/` would never run. It
    starts two full gateway stacks on two HTTP servers sharing one bus; with `FLEET_RELAY_TEST_REDIS_URL` set the
    bus is that Valkey. The two-PROCESS proof is the boot smoke below.

### PR 2 — pre-merge gate (2026-10-19, `627fa2ebf`, `0df0c4bc3`)

35. **A broadcast is accepted only after a handshake with its sender** (envelope version `3`). A replica that has
    never heard a sender has no sequence to compare with, so a broadcast captured before it started would pass a
    sequence check. It now drops a broadcast from a sender it holds no broadcast sequence for and asks that
    sender, in a message addressed to its own process id (random per process, so nothing addressed to it
    predates it), for its sequence; only broadcasts above the answer are accepted, and the sender is a peer only
    from then on. No signed timestamp: it would add a clock-skew failure mode and still admit a capture made
    seconds before start.
36. **`claimOnce` fails closed whenever a Valkey URL is configured**: down means every claim (so every link and
    viewer token) is refused on every replica. The earlier "a replica that never heard a peer keeps claims in
    process" (L5) let one token be accepted once per replica and never reached Valkey. Without any Redis URL the
    in-process bus keeps its own claims (single-replica dev).
37. **`FLEET_RELAY_BUS_ENABLED=false` is the bus's kill switch** (default on, the behaviour of decisions 25–27):
    every relay in-process even with `REDIS_URL` set, no code change. It wins over `FLEET_RELAY_REQUIRE_BUS`
    (a deliberate operator choice, not a missing URL) and the boot log says so. In `apps/api/.env.example`;
    CONTRACTS §9's flag table (program docs, not this lane's to edit) does not list it yet.
38. **The leave message on SIGTERM without app-wide shutdown hooks**: `RelayBusLifecycle` listens for SIGTERM and
    SIGINT itself (Valkey bus only), closes the bus (bounded 2 s) and re-raises the signal when nothing else
    listens, so the process still ends as before. Q6 (app-wide hooks) stays an owner question.
39. **Generations are fleet-wide.** `remember()` feeds a remote link's generation to the registry
    (`observeGeneration`), and a hello presenting a generation above this replica's record reads as continued:
    a node that bounced A → B → A no longer looks like a fresh process (which marked every running operation of
    the node interrupted, fleet-wide).
40. **The holder checks for itself**: it rebuilds a forwarded requirement with `resolveFleetLinkRequirement`
    (moved to `fleet-link-requirement.ts`, re-exported by the authoriser) and refuses a malformed one; re-checks
    the consent against the link's live consents; forwards only a family's own channel-0 types; bounds request
    timeouts (10 min), drain grace (3600 s) and close reasons from the bus; and closes an open whose caller
    closed or left before the node answered.
41. **Forwarded channels are reconciled** every directory sync: each replica tells each peer the refs it still
    knows (opened there, served for it) and the other side ends what is no longer listed, after a 10 s grace.

## Questions for the owner

- **Q1 (decision 7):** should read-only link requests (`health.now`) keep working while the fleet kill switch is
  on? Built: refused, per R-24 "every link request is refused". Allowing reads is a one-line change in
  `FleetLinkAuthorizer`.
- **Q2 (decision 2):** the capability-tag default rose from 16 to 32. Any deployment that pins
  `FLEET_MAX_CAPABILITY_TAGS=16` keeps working (nodes fall back), but loses the program's tags past the 16th.
- **Q3 (for the program docs, not editable by this lane):** CONTRACTS §3.1–3.2 does not yet name what the wire
  now carries: close codes `4001 · 4002 · 4003 · 4008 · 4009 · 4010 · 4012` (+ `1000`, `1001`), `requestId` on
  `channel.open|ready|refused`, `resumeKey` on `channel.ready`, `resumed`/`closed` on `link.ready`,
  `resume { linkGeneration, channels[] }` and `nodeVersion` on `link.hello`, and `channel.refused`'s
  `error: { code, hint }` (§3.2 abbreviates it). The constants and the wire fixture
  (`packages/contracts/fixtures/fleet-link-contract.v1.json`) are the source today; a CONTRACTS revision can
  copy them.
- **Q4:** `DELETE /api/fleet/operations/:id` is allowed for the requester or the node's owner, and works while the
  kill switch is on (a cancel stops work). The plan's table also names the operation's family audience: a
  requester whose audience was narrowed after starting the operation can still cancel it. Keep, or re-check the
  family on cancel?
- **Q5 (decision 27):** with `REDIS_URL` set, the terminal and computer relays now fan out across replicas
  (R-7 / FR-29 ask exactly this). A deployment that runs several API replicas with Redis gains it the day this
  ships; one that runs a single replica sees no difference. Any deployment where that change should wait?
  (Since decision 37 it can wait without a code change: `FLEET_RELAY_BUS_ENABLED=false`.)
- **Q6:** see "Next step" — enable Nest shutdown hooks app-wide? (The bus no longer needs it: decision 38.)
