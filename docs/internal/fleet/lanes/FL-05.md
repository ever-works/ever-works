## Decisions

1. **One state machine, in contracts** (`mergeFleetSessionEvidence`, `fleet-session-status.types.ts`): the node runs it;
   the platform writes what the node reports (newer `seq` only) and re-checks every shape. Plan §3 "the same function on
   the platform" — the platform does not re-merge, it trusts the newest report of the machine that saw the evidence and
   refuses only what the contract forbids (an ended session, a shell in `needs_you`/`done`).
2. **No sixth column for the card's lines.** The last user line and the last agent line ride `lastEvidence.detail`
   (`userLine`, `agentLine`), carried forward report to report (CONTRACTS rev 11) — the five §4.2 columns stay exactly
   five.
3. **One hook client, not shell scripts.** Plan §3 named `.sh`/`.cmd` scripts calling `curl` with a `node -e` fallback;
   the node binary is always there (it runs the node and its daemon), so the client is ONE Node script
   (`<state>/hooks/hook-client.cjs`) for Linux, macOS and Windows, and the endpoint file is one JSON file
   (`<state>/hook-endpoint.json`). It reads the endpoint file per invocation (U1), posts with the token, spools on any
   failure (U2), always exits 0 within 2 s and never prints (a Claude hook's stdout would become model context).
4. **`PostToolUse` is registered beside the spec's seven Claude hooks**: without it a permission answered in the
   terminal would leave the card in `needs_you` until the turn ended (U5). Mapped to a `working` hook evidence.
5. **Claude Code Agent sessions get no hook overlay**: the Task-run isolation runs them with `disableAllHooks`
   (FL-04 decision 37, never downgraded); their status comes from the process (and, P2, the screen rules). Owner
   question Q1.
6. **Codex: `-c notify=[…]` for owner AND Agent sessions.** Agent sessions run `--ignore-user-config` under an isolated
   `CODEX_HOME`, which would ignore a `notify` written into that home's `config.toml` (plan §6.1); the command-line
   override still applies. Owner sessions: the person's `config.toml` is only READ, to say "Your own Codex notify
   command is not run in this session" (U11). Codex has no prompt hook, so a `agent-turn-complete` is normalised to
   `prompt` + `stop` (the turn it completes is the prompt) so its finish is news.
7. **Interrupt = a driver's Ctrl-C in a running turn** (the session module tells the pipeline what a driver typed —
   facts only, bytes kept nowhere): `done · interrupted`, not news (U15). Claude's `Stop` does not fire on an interrupt.
8. **`session-end` never ends a row**: Claude fires `SessionEnd` on `/clear` too, and the process exit (FL-04's
   `exited`) follows a real end within milliseconds. It clears an open prompt.
9. **Boundary**: a `stop` with no prompt since the last start/resume, or inside the 5 s window after one, is a
   boundary — `done` without the `finished` key, so no unread and no notification (U12, FR-39).
10. **Idle floor folded into FL-04's sweeper** (`sweepStale` → `decayIdle`, every 5 min) instead of a second Trigger task
    (plan §10's `fleet-session-status-sweeper`): same cadence, one task. It decays only sessions whose machine link is
    up — a lost link never changes a state (NFR reliability); the node's own clock is primary.
11. **`stateChangedAt` is nullable** (back-filled by the migration from `lastActivityAt`, else `createdAt`; stamped on
    every state change by both writers) so the migration adds no NOT NULL column to a populated table.
12. **Version gating** (`CLAUDE_HOOK_MIN_VERSION`, `hook-overlay.ts`): an unknown Claude Code version gets every hook;
    a known older one loses the hooks it predates (U10). The table's minimum versions are best knowledge — owner
    question Q2.
