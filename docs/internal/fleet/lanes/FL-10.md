## Decisions

1. **Shared tables live in contracts.** The well-known names, the Windows / Unix noise tables, the loopback-URL check and
   the list sanitiser (`normalizeFleetPortsList`) are in `packages/contracts/src/fleet/fleet-ports.types.ts`, so the node,
   the platform, the tools and the web read one definition. The platform never forwards a node's list without
   `normalizeFleetPortsList`.
2. **`FLEET_PORTS_CAPABILITY` sits in `fleet-ports.types.ts`**, not `fleet-jobs.types.ts` (the FL-04
   `FLEET_SESSIONS_CAPABILITY` precedent: an epic's tag beside its types).
3. **`profile?: 'agent' | 'preview'`** for the `desktop` channel (CONTRACTS §3.3, T-02) is typed in
   `fleet-ports.types.ts` (`FleetDesktopChannelParams`) rather than FL-02's link file, which another lane is editing.
4. **The audit names** `node.port.open`, `node.port.preview.open`, `node.port.preview.close` are added to
   `FleetAuditAction` / `FLEET_AUDIT_ACTIONS` and the panic spec's list.
5. **CONTRACTS §4.9 revision 4 wins over plan §4.1:** the tunnel row carries `requestCount`, and `closedReason` admits
   `drain` and `link-closed` as well as the five of the plan.
6. **The node side is one `ports` module** (`apps/node/src/core/link/modules/ports/`): `discover.ts` (`ss -tlnpH` with a
   `-p`-less fallback, `lsof -F pcn`, PowerShell `Get-NetTCPConnection` + `Get-Process` as JSON via `-EncodedCommand`),
   `classify.ts` (noise BEFORE web; Windows PID 4/0 is noise unless it answered as a real server), `http-probe.ts`
   (loopback only — there is no host parameter; plain HTTP, then TLS on a protocol error; linear `<title>` scan +
   `redactSecrets`), `join.ts` (cwd per OS, `docker ps` port mappings only when a listener looks like a runtime proxy),
   `watch-list.ts` (waiting rows; "stopped" once, dropped next), `open-desktop.ts`, `preview-browser.ts`, `index.ts`
   (2 s list cache shared by every caller; system ports are never probed). Built by `runtime.ts` only under `--manage`.
7. **The preview picture rides the `desktop` family, so it needs `--attend`.** CONTRACTS §3.3 gives the `desktop` family
   the consent `attend`, and the platform's requirement resolver never lets a caller weaken a family's consent. The Open
   menu therefore offers the preview browser only with `--attend` (and says so). Question Q2.
8. **`desktop` family seam.** No `desktop` family existed on the node; `apps/node/src/core/link/modules/desktop.ts`
   (`createDesktopFamilyModule({ preview, agentBrowser?, desktop? })`) routes by `params.source` / `params.profile`.
   FL-10 fills `preview`; **FL-07 must add its sources to this module, not register a second `desktop` module**
   (`composeNodeModules` refuses a duplicate family at startup).
9. **Open on the desktop without FL-07:** the runtime binds a system opener (`xdg-open` / `open` /
   `rundll32 url.dll,FileProtocolHandler`, one argument, never a shell string) only when the node runs in a desktop
   session with `--attend`; the module then advertises `ports-desktop` (`FLEET_PORTS_DESKTOP_OPEN_CAPABILITY`), which the
   platform's Open menu reads. FL-07's helper replaces the opener (`portsDesktopOpener` runtime option).
10. **`PreviewPageSource`** extends the Agent capture page source (constructor/fields made `protected`, nothing else
    changed) with ONE verb, `navigate(url)`, refused for anything but `http(s)://127.0.0.1|localhost:<port>/`.
    `HeadlessPreviewBrowser` launches the probed browser headless in `~/.ever-works/preview-profile/browser` (env
    `EVER_WORKS_NODE_PREVIEW_PROFILE_ROOT`), owner-only (0700 / the Windows ACL), beside `agent-profiles`.
11. **Preview lifetime on the node:** one per node (`busy` naming the holder for another view), 30 s for the opener to
    attach, 15 s after the last viewer leaves, 60 min hard, ended at once by the kill switch (`link.pause`).
12. **Platform:** `FleetPortsService` (agent package) decides; `FleetPortsLinkAdapter` (API) binds `FLEET_PORTS_NODE_PORT`
    to `FleetLinkService.request` and to FL-02's viewer minter (`desktop` family, target = view id, role `driver`, params
    `{ source: 'browser', profile: 'preview', viewId }`). Only computers of kind `node` list ports (U16). The Open menu's
    decision is one pure function (`fleet-ports.policy.ts`) the list response and the open route share. An Agent's open
    gets no viewer token (the picture is for a person).
13. **Flags:** FL-09 landed `config.fleet.isMachineFactsEnabled()` and `FleetMachineFactsEnabledGuard`
    (`apps/api/src/fleet/machine/`) first; FL-10 reuses both (its own copy was dropped in the develop merge before it
    ever landed). `isPortTunnelEnabled()` (needs `FLEET_PREVIEW_HOST`) and `getPortPreviewHost()` are FL-10's, for P2.
14. **The `desktop` family module is FL-02's** (`createDesktopModule(broker)`, the live-view leg, merged while FL-10 P1 was
    open). FL-10 extended it additively: `createDesktopModule(broker | null, { preview?, desktop? })` — `source:
'browser', profile: 'preview'` goes to the preview source, every other `browser` channel to the leg broker exactly
    as before, `source: 'desktop'` to FL-07's source when it lands. `createDesktopFamilyModule(sources)` is the
    broker-less form. The runtime passes `desktopSources: { preview }` to `composeNodeLinkModules`.
15. **Palette:** "Ports on <computer>" only for computers advertising `ports` (FL-09's rows' rule).
16. **Runner:** discovery, joins and probes run through FL-09's machine runner (`createMachineCommandRunner`: `execFile`,

17. **A list stays inside the link's 2 s inline window:** probes are cached per port (4 s) and a list waits at most 1.4 s
    for fresh ones; a slower one finishes in the background for the next list. Anything that still outruns the window
    (a slow discovery, a preview browser starting) comes back as an operation, which the API adapter waits on through
    `FleetOperationsService` (200 ms polls, the caller's timeout).
18. **Preview browser switch:** `PATCH /api/fleet/nodes/:id { previewProfileEnabled }`, owner only, no audit row (the
    star's posture); web: a server action + `PreviewBrowserSwitch` in FL-01's Settings tab (one line added there).
19. **Palette:** a separate `fleetComputerPortsScreens` beside FL-01's `fleetComputerScreens`, so FL-01's spec of the
    latter stays as it is.
20. **Not updated:** the contracts barrel pin (`packages/contracts/src/fleet/__tests__/index.spec.ts`, 402) — it does not

### P2 (preview tunnel, `feat/fl-10-ports-p2`)

21. **Per-replica tunnel channels, the row is the shared state.** Each API replica opens its own `tunnel` channel per
    tunnel lazily on the first request it serves (`FleetLinkService.openChannel`, so a link held elsewhere is reached
    through the relay bus) and closes it after two idle minutes. Every request is authorised against the
    `fleet_port_tunnels` row first, so a tunnel closed on one replica is refused on all at their next request — no
    cross-replica tunnel state. The channel open is `stateChanging: false` (no `node.link.channel-open` row): the tunnel's
    own open and close rows are its record — exactly two per tunnel (ACC-FL10-18). The link's gate still refuses the
    open under the kill switch.
22. **Auth = the hand-off, always.** The web's session cookie (`everworks_auth_token`) is host-only, so it never reaches
    the preview host: R-17's primary path cannot work here, and its documented fallback is the mechanism — a 60-second,
    single-use (per replica) HMAC hand-off `?t=` on the address the person opens, traded at once for an HttpOnly,
    Secure, SameSite=Lax cookie `ew_ta_<id>` valid until the tunnel's hard end, then a redirect that drops `t` from the
    address. Every request re-checks the row (open, unexpired, same owner, fleet not stopped). Question Q5.
23. **Wire:** `[request u32]` prefixes every `DATA`/`END` body chunk so many requests share one channel (≤ 32); JSON
    envelopes `tunnel.request|response|error`. `tunnel` is not a credit family (CONTRACTS §3.2 lists `files`, `logs`), so
    there is no `ACK` window: a slow browser is buffered by the API. Question Q6.
24. **Preview host** (`apps/api/src/fleet/ports/preview-host.handler.ts`) is mounted in `main.ts` before the body parsers,
    helmet and the router, and answers every request whose `Host` is exactly `FLEET_PREVIEW_HOST` itself — nothing on
    that host reaches a platform route. Request: hop-by-hop + credential headers dropped (`authorization`, forwarded-for
    …), `ew_*` and the web's session cookie removed from `cookie`. Response: hop-by-hop dropped, `Set-Cookie` unchanged,
    an absolute `Location` on the port rewritten (a redirect elsewhere becomes a page with the link, U13), the sticky
    `ew_tunnel` cookie set on prefixed pages for root-absolute assets. Own pages: 401/403/404/410/502/504, plain HTML.
25. **Sweeper:** an API `@Cron` every minute (`17 * * * * *`) under `DistributedTaskLockService`, on every install — no
    Trigger.dev task (the close is a CAS, so overlap is harmless). Reasons: `kill-switch`, `hard`, `idle`, `node-offline`
    (node removed / disabled / no link and no beat for 2 min — the trigger in the close row). The request path also
    closes an expired or stopped tunnel at its next request. **Drain is not detected** (no drain hook wired): Q7.
26. **Agents:** `fleet_ports_preview_open` opens the tunnel for the Agent's owner and returns its address WITHOUT a
    hand-off (spec U15); the owner opens it from the Ports tab. MCP exposes only the close (the open's answer carries a
    one-time address into the owner's tunnel).
27. **Web:** "Preview in my browser" on each web row when `tunnel.available`; the previewing state (time left, requests,
    bytes, Open again, Close preview, Copy link — the plain address, never the hand-off); the new tab is opened inside the
    click (blank, `opener` cleared) so it is not blocked, then pointed at the one-time address.

### P3 (WebSocket passthrough, watch, docs — `feat/fl-10-ports-p3`)

28. **WebSockets are relayed raw, not re-framed.** The preview host passes the browser's upgrade (its
    `Sec-WebSocket-Key`, protocols, extensions) to the node as `tunnel.ws-open`; the node makes the SAME upgrade to the
    loopback port and answers `tunnel.ws-accept { status, headers }` (or `tunnel.ws-refused { status }`); from then on
    the two byte streams travel as `DATA [request u32][bytes]` both ways until `END`. WebSocket frames are never parsed,
    so any subprotocol and compression the two ends agree on works (plan §3 sketched an opcode prefix; the raw relay is
    simpler and protocol-agnostic). An open socket touches the tunnel every minute (FR-32's "activity").
29. **The other upgrade listeners leave the preview host alone.** The terminal gateway destroys every upgrade it does
    not own (and any with a query string — which a hot-reload socket has), so the terminal, computer and fleet-link
    gateways each gained one first line: `if (isFleetPreviewHostRequest(req)) return;`
    (`apps/api/src/fleet/ports/preview-host.match.ts`) — false whenever no preview host is configured, so nothing changes
    elsewhere.
30. **Watch (FR-33)** is the tab's state: a watched port that was live and stops raises an inline notice and asks the
    platform (`POST /api/fleet/nodes/:id/ports/:port/watch-stopped`) to file ONE Inbox item through `INBOX_PRODUCER`
    (`view` audience; at most one per person, computer and port per five minutes, in memory per replica).
31. **User doc** `docs/features/fleet-ports.md`, sidebar entry after Logs, row in `docs/features/index.md`.

## Questions for the owner

- **Q1 — `previewProfileEnabled` defaults OFF.** Spec FR-12 says default on; FL-02's migration
  `1796020000000-AddFleetNodeConsents` (already merged) created the column with default `false`. Built: the column as it
  is — **Open in the preview browser** is disabled until the owner switches the preview browser on in the computer's
  Settings tab (the sentence says so). Flipping the default is a migration on a merged column.

- **Q2 — consent for the preview browser.** Its picture rides the `desktop` family, whose CONTRACTS §3.3 consent is
  `attend`; the spec reads as if `--manage` alone should do. Built: `--attend` required (the stricter reading). A
  per-params consent for `desktop` with `profile: 'preview'` would be a CONTRACTS change.
- **Q3 — links clicked inside the preview.** `navigate` is loopback-only, but the person driving the preview browser
  can follow a link on the page to another site (it is their machine's browser). Built: allowed. Blocking it would
  also break pages whose assets come from a CDN.
- **Q4 — audit the preview-browser switch?** Built like the favourite star: no audit row. CONTRACTS §7 has no name for it.
- **Q5 — the session cookie on the preview host.** R-17 prefers the platform session cookie on a shared cookie domain;
  this platform's cookie is host-only, so the hand-off is used every time. Consequence (U12): a signed-in person who is
  NOT the owner and opens the bare address has no tunnel cookie, so they see "open it from Ever Works" (401), not "belongs
  to someone else" (403) — the 403 is shown only when a valid tunnel cookie names another person. A shared-domain session
  cookie (and a resolver) would allow the exact U12 behaviour.
- **Q6 — no flow control on the tunnel.** `tunnel` is not a credit family in CONTRACTS §3.2; a slow browser makes the API
  buffer. Adding `tunnel` to `FLEET_LINK_CREDIT_FAMILIES` would be a CONTRACTS change.
- **Q7 — drain.** Drain-all does not close tunnels yet (spec FR-25 lists drain); the sweeper closes them `node-offline`
  only when the node goes away. Wiring the drain notifier is a follow-up.
