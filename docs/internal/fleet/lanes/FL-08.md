## Decisions

1. **The service lives in the API, not the agent package.** Plan §5 put `FleetLogsService` in
   `packages/agent/src/fleet/logs/`, but the node link (`FleetLinkService`, the viewer minter and gateway) is
   API-side (`apps/api/src/fleet-link/`), and the agent package must not import the API. The service, the
   controller, the viewer observer and the flag guard are `apps/api/src/fleet/logs/`; the Agent tool factory
   stays in the agent package and reaches the read through a port (`FleetLogsReaderPort`) the API can bind.
2. **Nothing streams until the reader asks** (plan §6 step 2): the channel opens, then the browser sends
   `logs.follow { on: true, lines }` after `viewer.ready`, and the one-shot read sends `logs.read { lines }`.
   No race between `channel.ready` and the first `DATA`.
3. **Source ids are self-describing** (`file:/var/log/syslog`, not `file:<sha1>`): the node needs the path to
   open it anyway and re-validates it against its roots on every open; a typed path is then just another id.
   Ids are bounded at 400 characters so a viewer token's params stay inside FL-02's 512-byte bound.
4. **Redaction marker** is the shared scanner's own (`[redacted secret]`), not a second spelling.
5. **Audit rows on the viewer path are written when the batch completes** (`logs.initial-done`), so they carry
   the real line and redaction counts (FR-27): the viewer gateway gained one additive optional observer hook
   (`nodeMessage`) that sees the node's JSON control messages on the channel — never a `DATA` payload.
6. **Pause is the viewer's** (FR-15 counts arrivals while paused): the browser keeps receiving and holds what
   arrives; the node still implements `logs.pause` / `logs.resume` (≤ 1 MiB held, oldest dropped and counted)
   for a reader that wants to save the link.
7. **Root-only files and the Security log without elevation refuse `unsupported_on_node`** with the hint the
   spec writes (U6, U7) — `permission_denied` is the platform audience's code.
8. **Per-viewer channel cap (8) is per API replica**, like FL-04's viewer cap: a courtesy limit that keeps one
   person inside the link's 64-channel budget, not a security boundary.

9. **A launchd service's own log file is read even outside the roots** (macOS): FR-9 says a service opens "the
   lines the service manager attributes to it", and launchd attributes them to the job's `StandardOutPath`
   (else `StandardErrorPath`). The path comes from `launchctl print` for a job the listing named, never from
   the caller; without one the job's process records in the unified log are read instead.
10. **Event logs and the unified log do not page back yet** (`supportsEarlier: false`); the journal and files
    do. The node already merges up to 12 sources by time and answers `logs.earlier` (lines marked
    `earlier: true`) — P2 adds the browser side (chips, **Load 500 earlier**, FL-09 deep links).
11. **The Agent tools are built but not assembled by default** — exactly as FL-03's health tools: the agent
    package offers `buildFleetLogsTools` when `AgentFleetToolSource.logs` is bound, and the API binds the port
    (`FLEET_LOGS_READER` → `FleetLogsService`); FL-19 owns the catalogue and binds it behind the Agent gates.
    The MCP whitelist gains `fleet_logs_sources` / `fleet_logs_read` (`follow` cut from the tool).
12. **The palette entry needs the hub flag too** (`isFleetMachineFactsEnabled()` = hub on and
    `FLEET_MACHINE_FACTS_ENABLED`), passed down beside `fleetHubEnabled` (one more optional prop and context).

13. **The allowed-roots resolver is FL-14's** (it landed first, R-39): FL-08's realpath half
    (`resolveCanonicalAllowedRoots`, `resolveUnderRoots`, `standardLogDirs`, `isInsideRoot`,
    `isFilesystemRoot`) joined THAT module (`apps/node/src/core/link/allowed-roots.ts`) under new names; FL-14's
    `resolveAllowedRoots` / `isWithinAllowedRoots` are untouched. Ready checkouts come from FL-14's
    `checkoutsModule.readyPaths()` (R-41). `--files-root` (FL-08 lands it) feeds `extraRoots`.
14. **FL-09's guard is reused** (`apps/api/src/fleet/machine/fleet-machine-facts-enabled.guard.ts`); FL-08 keeps no
    second one. FL-09's Services tab links `?tab=logs&source=service&unit=<name>`; the Logs tab reads that shape as
    well as `?source=<id>` (`logsDeepLinkSource`).

### PR 2 (P2 — merged view, earlier, hand-offs)

15. **Merged views open from a deep link or ctrl/cmd-click** in the source list (up to 12): one viewer, lines
    merged by time on the machine, a coloured chip per source. One source ending (`gone` / `stopped`) leaves the
    others following and says so under the list.
16. **Deep links** (`components/fleet/logs/logs-tab.registry.ts`): `openLogsForSource(nodeId, id, { at? })`,
    `openMergedLogs(nodeId, ids, { title? })` (repeated `?source=`, `&title=` names a Compose project),
    `composeLogSourceIds(names)`. FL-09's Compose view ("arrives with the next update" on develop) should call
    `openMergedLogs(node.id, composeLogSourceIds(project.containers), { title: project.name })` — FL-08 does
    not edit FL-09's DockerTab.
17. **Load 500 earlier** pages one source back: the journal (`--until` + cursor), files (backward scan) and
    now the event logs (`TimeCreated < oldest`); a container says the Docker log driver bounds it; the unified
    log says it has no earlier lines. The view keeps the reader's place when a page is prepended. Merged views
    do not page back (one source at a time).
18. **Viewer-token params stay ≤ 512 bytes** (FL-02): twelve long file paths can exceed it and are refused
    `invalid` at mint; Compose containers fit comfortably.

### PR 3 (P3 — open the log at a failure, download)

19. **"Open the log" is the Services tab's existing per-row Log entry**, given the failure time for a failed
    row (`openLogsForSource(node, 'service:<name>', { at: service.since })`, one additive change in FL-09's
    `ServicesTab.tsx`). The Logs tab positions at the first line at or after `at`, highlights it, and pages back
    up to four times when the failure is older than the batch. No "needs a look" producer is added — CONTRACTS
    §4.6 has no failed-service kind yet (spec §8b); when it has, the same link is that item's action.
20. **Download shown lines** builds a Blob of the filtered held lines in the browser (`logsDownloadName`), the
    lines already scanned on the machine; the platform stores nothing (FR-40).

21. **FL-09's Compose Logs link is `?source=compose&project=<name>`** (its `ComposeView.tsx`): the listing now
    reads each container's `com.docker.compose.project` label into the source's `group`, and the Logs tab opens
    that project's containers merged (≤ 12) under the project's name once the list is in. The log listing's
    buffered commands run through FL-09's `createMachineCommandRunner` (execFile, no shell): on Windows the node's
    own probe runner goes through `cmd.exe`, which would mangle `docker ps --format`'s braces and quotes.
